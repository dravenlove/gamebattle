## A. C++ 基础

**1. `struct` 和 `class` 的区别？**
只有默认访问权限不同：`struct` 默认 public，`class` 默认 private。习惯上 `struct` 用于纯数据，`class` 用于有不变量要保护的类型。（课 3）

**2. 空类的 `sizeof` 是多少？**
1。每个对象都必须有唯一的地址。但作为基类时可以占 0 字节（**空基类优化**）：实测 `sizeof(Empty)=1`，空基类加一个 `int` 的派生类是 4，空类作为成员加一个 `int` 是 8（1 字节加 3 字节对齐填充）。C++20 的 `[[no_unique_address]]` 让成员也能享受这种优化。

**3. 结构体的内存对齐？怎么减少填充？**
每个成员按自身的对齐要求放置，结构体整体大小是最大对齐值的整数倍。实测 `{char, int64, char}` 是 24 字节，调整为 `{int64, char, char}` 后是 16 字节。**按成员大小从大到小排列**可以减少填充。

**4. `const` 的几种用法？**
修饰变量（不可修改）；修饰指针（`const T*` 指向的内容不可改，`T* const` 指针本身不可改）；修饰引用参数（只读借用）；修饰成员函数（不修改对象，`const` 对象只能调用 `const` 成员函数）。（课 2）

**5. `const` 和 `constexpr` 的区别？**
`const` 表示"运行期不可修改"，值可以在运行时才确定；`constexpr` 要求编译期就能求值。`constexpr` 函数可以在编译期调用，用于生成查找表等。（课 15）

**6. `static` 的几种含义？**
函数内的 `static` 变量：只初始化一次，生命周期到程序结束，C++11 起初始化是线程安全的（课 9 的 `static Handler`）；类的 `static` 成员：属于类而不属于对象（课 5 的 `TargetSelector::select`）；文件作用域的 `static` 函数或变量：只在本文件可见，现代写法是用匿名 `namespace`（课 1）。

**7. `#define` 和 `const` / `constexpr` 的区别？**
宏是预处理阶段的纯文本替换，没有类型、没有作用域、调试器看不到，容易出现优先级问题。常量和 `constexpr` 有类型检查和作用域。除了条件编译（`#ifdef _WIN32`，课 9）和少数需要 `__FILE__`、`#` 字符串化的场合（课 11 的 `CHECK` 宏），都应该用常量代替宏。

**8. `inline` 关键字现在是什么意思？**
主要含义已经变成"允许在多个翻译单元中重复定义（只要定义相同）"，所以头文件里定义的函数要加 `inline`，否则链接时报重复定义。是否真的内联由编译器决定。C++17 的 `inline` 变量同理。

**9. `extern "C"` 有什么用？**
让函数按 C 的规则命名，不做 C++ 的名字修饰。实测 `nm` 显示 C++ 函数 `cpp_linkage(int)` 的符号名是 `_Z11cpp_linkagei`，而 `extern "C"` 的 `c_linkage` 就是 `c_linkage`。和 C 库互相调用、导出动态库接口时需要它，Erlang 的 NIF 接口（`erl_nif.h`）就是 C 接口。

**10. `new` / `delete` 和 `malloc` / `free` 的区别？**
`new` 分配内存并调用构造函数，失败时抛 `std::bad_alloc`；`malloc` 只分配原始内存，失败时返回 `NULL`。`delete` 先调用析构函数再释放。不能混用；`new[]` 必须配 `delete[]`，实测 `new std::string[3]` 配 `delete` 被 ASan 报告为错误。现代 C++ 应该用 `make_unique` / `make_shared`，几乎不需要手写 `new`。（课 14）

**11. 什么是 placement new？**
在一块已有的内存上构造对象：`new (buffer) std::string("...")`。实测对象的地址就是 `buffer` 的地址。用完必须**手动调用析构函数**，不能 `delete`。内存池、`std::vector` 的内部实现都依赖它。

**12. 引用和指针的区别？**
引用必须在定义时初始化、不能改绑、不能为空，语法上像变量的别名；指针可以为空、可以改指向，用 `->` 访问成员。函数参数里，"一定存在"的用引用，"可能没有"的用指针。（课 2）

**13. 能返回局部变量的引用吗？**
不能。局部变量在函数返回时就销毁了，返回的引用立即悬空。`-Wall` 会警告：实测 `warning: reference to local variable 'name' returned`。应该按值返回，编译器会做复制省略（课 13）。

**14. 四种类型转换？**
`static_cast`：编译期检查的普通转换。`dynamic_cast`：运行时检查的多态向下转换（课 12）。`const_cast`：去掉 `const`（修改原本就是 `const` 的对象是未定义行为）。`reinterpret_cast`：按位重新解释，基本只用于"把对象当字节看"（课 9）；需要按位转换数值时用 C++20 的 `std::bit_cast`。

**15. 什么是未定义行为？举几个例子。**
标准不规定结果的行为，编译器可以假设它不会发生，并据此优化。例子：有符号整数溢出（实测"先算后查"的溢出检查被 `-O2` 整个删掉，课 7）、越界访问、使用已释放的内存、数据竞争（课 17）、空指针解引用、通过基类指针删除没有虚析构函数的子类对象（课 12）。

**16. `explicit` 有什么用？**
禁止单参数构造函数被用作隐式转换。实测没有 `explicit` 时，把 `simulate(battle_id, Random(seed))` 写成 `simulate(seed, battle_id)` 能编译通过，两个参数被悄悄对调。（课 3）

**17. lambda 的捕获方式？有什么陷阱？**
`[x]` 按值、`[&x]` 按引用、`[=]` / `[&]` 自动捕获、`[this]` 捕获当前对象。陷阱：按引用捕获的 lambda 被存起来或交给别的线程、比被捕获的变量活得久，就会悬空。（课 5、17）

## F. 并发

**55. 进程和线程的区别？**
进程有独立的地址空间，崩溃互不影响，切换开销大；同一进程内的线程共享地址空间（堆、全局变量、文件描述符），各有自己的栈和寄存器，切换开销小，但一个线程崩溃会导致整个进程退出。Erlang 的"进程"是虚拟机调度的轻量进程，概念上更接近隔离的进程，开销却比线程还小。（课 17）

## G. 网络

**68. TCP 和 UDP 的区别？游戏里怎么选？**
TCP：面向连接、可靠、有序、有流量和拥塞控制，丢包时后面的数据要等重传（队头阻塞）。UDP：无连接、不保证可靠和有序，开销小、延迟低。回合制和大多数 MMO 用 TCP 就够了；对延迟极敏感的动作类、射击类游戏常用 UDP，并在其上自己实现可靠性（比如 KCP：用更多带宽换更低延迟的可靠 UDP 协议）。

## H. 操作系统

**80. 虚拟内存是什么？有什么好处？**
每个进程看到的是独立的、连续的虚拟地址空间，由 MMU 通过页表映射到物理内存。好处：进程之间隔离；可以只把用到的页面放进物理内存（按需分页）；可以过量分配。课 22 的问题 2 就是一个例子：预留了 3.8 GB 虚拟内存，物理内存只用了 4 MB。

**81. 什么是缺页中断？**
访问的虚拟页面还没有映射到物理内存时，CPU 触发缺页异常，内核分配物理页（或从磁盘读回来）、建立映射，再继续执行。第一次写入新分配的大块内存时会产生大量缺页，这也是"预热"的原因之一（课 21）。

**82. 用户态和内核态？系统调用的开销？**
应用程序运行在用户态，访问硬件、文件、网络必须通过系统调用进入内核态，要切换特权级、保存和恢复寄存器，一次通常在几百纳秒到几微秒。高性能服务器设法减少系统调用次数：epoll 一次返回多个事件、eventfd 合并通知、批量读写、`io_uring`（课 19 的 strace 统计）。

**83. 进程间通信有哪些方式？**
管道（本项目的 Erlang Port 就是通过标准输入输出管道通信，课 9）、Unix 域套接字、TCP、共享内存（最快，但需要自己同步）、消息队列、信号。

**84. `fork` 的写时复制是什么？**
`fork` 后父子进程共享同一份物理页面，都标记为只读；任何一方写入时才复制那一页。所以 `fork` 很快，Redis 的 RDB 持久化就是利用它在子进程里保存快照。

**85. 什么是上下文切换？为什么线程不是越多越好？**
CPU 从一个线程切换到另一个线程，要保存和恢复寄存器、可能刷新缓存和 TLB。线程数远超核数时，大量时间花在切换和锁竞争上。（课 17：实测 4 个工作线程时空任务的调度开销是 1 个线程的 10 倍）

**86. 信号是什么？多线程程序里怎么处理？**
内核异步通知进程的机制，比如 SIGSEGV（段错误）、SIGPIPE、SIGTERM。多线程程序里信号可能被递送到任意线程。推荐做法：在创建线程前屏蔽信号，用 `signalfd` 在事件循环里统一处理（课 19）。

**87. 段错误一般是什么原因？**
访问了没有映射或没有权限的内存：空指针、越界、使用已释放的内存、栈溢出（递归太深，课 6 的深度上限就是为了防止这个）。用 core dump + gdb 定位（课 22）。

## I. 数据库与缓存

**88. MySQL 的索引为什么用 B+ 树？**
B+ 树矮而宽，一个节点对应一个磁盘页，几层就能存几百万条记录，查询只需几次磁盘读取；数据都在叶子节点，叶子之间用链表相连，范围查询很快。哈希索引不支持范围查询，二叉树太高。

**89. 聚簇索引和二级索引？什么是回表？**
InnoDB 的主键索引叶子节点存整行数据（聚簇索引）；二级索引的叶子节点存的是主键值，查到主键后还要回到主键索引里取整行，这叫回表。查询的列都在二级索引里时（覆盖索引）就不用回表。

**90. 事务的 ACID？隔离级别有哪些？**
原子性、一致性、隔离性、持久性。隔离级别从低到高：读未提交、读已提交、可重复读（InnoDB 默认）、串行化，分别解决脏读、不可重复读、幻读问题。InnoDB 用 MVCC 和间隙锁实现可重复读。

**91. Redis 为什么快？常用数据结构？**
数据在内存里，命令执行是单线程的（没有锁竞争），用 I/O 多路复用处理网络。常用结构：String、Hash、List、Set、ZSet（跳表 + 哈希表，排行榜，课 20）。

**92. Redis 的持久化方式？**
RDB：定期 `fork` 子进程把内存快照写入磁盘，恢复快，但可能丢失最后一次快照之后的数据。AOF：记录每条写命令，可以配置每秒刷盘，数据更安全，文件更大。生产环境常常两者结合。

**93. 缓存穿透、击穿、雪崩？**
穿透：查询根本不存在的数据，每次都打到数据库；用布隆过滤器或缓存空值解决。击穿：某个热点 key 过期的瞬间，大量请求同时打到数据库；用互斥锁重建缓存或让热点永不过期。雪崩：大量 key 同时过期或缓存服务宕机；过期时间加随机值、多级缓存、限流降级。

**94. 游戏里的玩家数据怎么落地？**
玩家上线时加载到内存，修改时标记为脏，定期或下线时批量写回数据库；涉及货币、道具的操作先写流水日志；结算以 `battle_id` 做幂等。（课 20）

**115. 为什么要用 C++ 写战斗，而不是直接用 Erlang？**
战斗是计算密集型任务：上千个事件、递归触发、频繁的数值运算。Erlang 擅长并发和容错，不擅长这类紧密的数值计算。用 C++ 写战斗，Erlang 负责连接、业务和调度，各取所长。

## M. Erlang 与 C++ 对比

**125. Erlang 进程和 C++ 线程？**（课 17）
**126. Erlang 的 "let it crash" 在 C++ 里怎么实现？**
C++ 没有进程隔离，一处崩溃整个进程退出。做法是把可能崩溃的部分放进独立的操作系统进程（本项目的 Port），由外部的监督者（Erlang 的监督树、systemd、k8s）负责重启。进程内部则用异常 + 边界上的 `catch (...)` 把错误转换成返回值（课 8）。

**127. Erlang 的 GC 和 C++ 的内存管理？**
Erlang 每个进程有独立的堆，按进程分别回收，不会全局停顿；大 binary 放在共享堆上引用计数。C++ 没有 GC，靠 RAII 和智能指针确定性地释放；`shared_ptr` 类似大 binary 的引用计数，但处理不了环（课 2、14）。

**128. Erlang 的热代码加载和 C++ 的热更新？**（课 20）

**129. NIF 为什么危险？**（课 8、9：运行在 BEAM 进程内，崩溃或异常泄漏会让整个节点退出；长时间运行要用 dirty scheduler）

## N. 算法

这套课程没有系统讲算法题，但几乎所有公司的笔试和面试都会考。建议：

- **刷题范围**：LeetCode 热题 100 足以覆盖大部分面试，重点是数组与双指针、哈希表、链表、栈与队列、二叉树、堆、二分查找、动态规划、图的 BFS/DFS、并查集。用 C++ 刷，同时练熟 STL。
- **游戏里常见的算法**，面试时可能直接问：
  - **加权随机**（掉落表）：前缀和 + 二分查找，O(log n)；别名法（alias method）可以做到 O(1)。
  - **洗牌**：Fisher-Yates 算法；`std::shuffle` 配合固定种子的随机数引擎就能复现结果（注意第 3 课：引擎算法固定，但"分布"在不同标准库上可能不一致）。
  - **寻路**：A* 算法（Dijkstra 加启发函数）；大地图用分层寻路或导航网格。
  - **Top K**：堆（`std::priority_queue`）或 `std::nth_element`（课 16）。
  - **限流**：令牌桶、漏桶。
  - **LRU 缓存**：哈希表 + 双向链表。
